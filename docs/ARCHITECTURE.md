# Architecture and trust boundaries

## Product and runtime

Pebble uses a native Tauri 2 window, the operating system webview, and Vue 3/TypeScript. Its custom avatar renderer samples a pinned bloub pebble engine at 30 fps. Reduced motion and document visibility stop sampling. Model Markdown is sanitized; it cannot execute scripts or load remote images. An explicit click on an HTTPS citation opens it in the system browser through a separate UI-only command.

Rust launches a frozen Python service and speaks bounded JSON over private stdio. An RPC allowlist connects the trusted local UI to the service. Model output has no path to that dispatcher. The service owns a native llama.cpp child on a random loopback port, protected by a private key never exposed to the renderer. One root task owns the service at a time. Inside it, root and child cloud inference share at most three concurrent requests; local GGUF children reuse the single resident worker through one lane. Service shutdown stops the model; five idle minutes unload it. The bundle excludes the 2.80 GB external GGUF. Consumer inference needs no Python/Node installation; test recipes need a development runtime.

## Small-model harness

The loop is bounded context → model step → schema validation → policy → AgentGuard → tool result → next step. The model sees a small file inventory, focused reads, and recent messages. The native chat template and tokenizer measure prompts and reserve output capacity. Compaction removes complete older tool exchanges (the call and all matching results) before dropping retrieved memory. A separate broker checkpoint retains inspected file paths/hashes, action status and execution evidence; it is protected alongside the current user task. The latest tool exchange stays intact. Source excerpts can be shortened without breaking JSON. This follows the user’s suggestion to reclaim old tool-call context. Oversized tasks fail visibly.

Tools include scoped source inspection/editing, isolated tests, app launch, current weather, web search/source reads, terminal commands, skills and allowlisted MCP calls. The intent router exposes only relevant schemas to preserve the 4K budget. Weather and exact app-opening requests bypass inference; weather never falls back to opening an app. General tasks have at most seven steps; coding/canvas tasks allow up to 24. Completed large file-write exchanges can leave the local prompt after the broker retains their path/hash/status and full audit record. Short calls, adaptive output reservation, bounded truncation recovery and phased website creation reduce small-model failure. A managed static preview starts from verified file receipts when the human explicitly requests localhost; it does not execute an arbitrary development command.

Ask stages effectful actions. Auto applies project edits/tests and confined read-only commands. Full access permits supported effectful tools without review while preserving confinement and disabled-tool switches. Destructive/unknown execution and network commands, hook review decisions on effectful actions, and plugin calls always stage review. A review hook on a read stops execution because read approvals are not implemented. Privileged/shell-wrapper commands are refused. Documents cannot expand the task’s tool menu. Offline document summaries and general questions expose no web tools unless the current user requests web/current information. Forged calls to unexposed tools fail schema validation. Permission configuration is snapshotted per task, cannot change during a task, and is unavailable to model tools or the pet window. The pet can only chat, cancel, view state and open citations; settings live in the full workspace.

Design references include [Claude Code's exploration and evidence-based verification workflow](https://code.claude.com/docs/en/best-practices), [Codex's separation of approvals and sandbox enforcement](https://developers.openai.com/codex/security/), and [FrogNano's tool-and-test training/harness](https://github.com/microsoft/FrogNano). These public references do not reveal proprietary internal architectures. [DeepSeek V3.2-Exp](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp) documents a model/inference release rather than a directly reusable desktop agent harness; its scale is inappropriate for this machine. A second resident planner/verifier model would consume scarce memory without creating an independent security boundary.

## Authority and source data

Only direct UI operations grant a project folder, source URL, or action approval. PDF text, repository content, filenames, web content, prior assistant messages, and test output are untrusted data. Prompt markers help interpretation; deterministic controls enforce authority even if the model follows an injected instruction.

Project paths must be relative and inside the selected root. Traversal, symbolic links, credentials, .git, model weights, root/home selections, and oversized reads are refused. AgentGuard indexes a filtered mirror under application data, preventing repository-root discovery from widening access. The adapter suppresses mutation bookkeeping on reads and refreshes its mirror with staged edits.

Approval retrieves an opaque action from host-owned SQLite. The caller cannot supply a replacement payload. Apply checks the original hash, preserves mode, writes through a same-directory temporary file, and replaces atomically. Undo checks the applied hash. Stale files, dismissed actions, invented IDs, and another conversation's IDs are refused. These protect against model errors and ordinary concurrent editing; an already compromised OS/user account or a hostile local filesystem race is outside the guarantee.

## AgentGuard

AgentGuard receives session, direct user prompt, pre/post tool, stop and session-end events. Non-allow pre-tool decisions stop a proposed project operation; a terminal REQUEST_REVIEW can instead stage the exact command for the user. Terminal events use AgentGuard’s Bash event adapter. The broker independently rejects commands and enforces the sandbox. Stop findings appear as visible verification requirements; drafts are not presented as validated completion.

AgentGuard is a verification and evidence layer, not a security layer. It is structurally fail-open internally. It checks reliability and cannot replace the broker. If initialization fails, protected project tools are disabled. Even ALLOW cannot override project confinement or authorize an action.

**Evidence the gate reads.** AgentGuard never reads test output. A test recipe reaches it as the host's classification (`=== N passed ===` only when the run exited 0 with a parsed positive count); a test command run through the terminal (`RunCommand`, or `StartCommand` with a terminal `ReadProcess`) as its exit code plus the counts Pebble's own parser read. A terminal run whose output proves nothing is recorded but is neither evidence nor a test run. A lint, build or typecheck pass is never test evidence; it only replaces an earlier failure of the same recipe. The latest run of a recipe (or terminal command) replaces its earlier failures only when it passed on the project's current files, and a pass on files changed since is no evidence. Pebble, not AgentGuard's phrase list, decides the test waiver: only an imperative ("do not run the tests") waives it. Changes an approved command made are synced into the mirror and count as changes. When the index is not ready at the stop gate, a run that changed source files is held as "verification unavailable", never allowed. Completion issues are built from these structured fields; a summary that did not come from the host would be JSON-quoted under an "untrusted test output" label, so project output never speaks in the host's voice. Written `.json` and `.csv` files must parse (and match the keys or header the request lists) before a run completes.

**Lifecycle.** Each project root has one mirror under `guard-projects` (the four most recently used are kept), synced incrementally from the broker's file view; the per-run drafts are written in as an overlay of the session that staged them, and a rejected, replaced-then-refused or undone draft leaves it again. The index builds and refreshes in the background: nothing waits for it before the first model request; the first mutating check and the stop gate wait for it, outside the adapter's lock and bounded. A run that reaches a terminal state ends its AgentGuard session (retention runs then: events 7 days, decisions 14, verifications 30, task and session summaries 30, metrics 14); a held run keeps its task until the person decides. Deleting a conversation deletes its sessions' rows (prompts, events, decisions, findings, challenges, verifications) with `GuardAdapter.forget`. Mirrors a crashed service left behind are removed when the next service starts. AgentGuard's planning budget (the `user_prompt` decision's additional context) is computed and deliberately withheld from the model: it is not measured against Pebble's own context budgets.

**Typed process input.** `WriteProcessInput` text is screened statelessly (AgentGuard's command patterns plus a few REPL patterns such as `shutil.rmtree`): the same text is refused every time, never lifted by a retry. This screen only narrows; the boundary is the person's review of the interactive plan plus the sandbox, and it does not understand arbitrary REPL code.

**Held tasks.** A run held at "verification required" offers three main-window decisions: run the covering tests (staged as the run's own action through the normal approval), ask Pebble to finish (the run resumes with exactly one fresh completion repair), or accept it as unverified (recorded with the person as origin; the receipt still reads "Not verified"). Each checked reply's receipt reads "Verified · …" or "Not verified · …" from a content-free summary (counts and the runner's name).

## Isolation and networking

Approved tests use a filtered temporary project copy and staged drafts. The macOS Seatbelt profile denies by default, permits necessary system/toolchain reads and dyld ancestor directory handles, and allows writes only in the snapshot. It grants no network rule. Output, duration, and descendant lifetime are bounded. The original project, home file contents, and network remain inaccessible in tested cases. The deprecated sandbox-exec interface needs broader malicious-code evaluation and a supported production replacement. Windows terminal and test execution fail closed.

Terminal commands are parsed to argv and executed with shell=False, with no pipes, redirects, substitutions or environment overrides. Seatbelt confines reads/writes to necessary system/toolchain paths and the selected project, denies credential paths, isolates HOME, and inherits into child processes. Read-only commands have no project write grant. Network is absent unless that exact command has a reviewed grant. Commands have a 60-second/output cap and descendant cleanup. Pattern classification is not a proof of safety; OS confinement remains necessary.

Web tools and explicitly attached URLs use a constrained public-source reader. Search returns unverified snippets; the model is instructed to read original sources for precise claims. Weather uses geocoding and forecast APIs, validates location, date, units and finite ranges, rejects stale data, and formats the answer deterministically. Conditions are modelled estimates, not claimed physical observations. HTTPS certificates are verified. All DNS answers must be public; the validated IP is pinned while hostname verification/SNI are preserved. Private networks, credentials, custom ports, redirects, binary responses, and oversized pages are refused. Script/style text is discarded; page JavaScript never runs. PDFs use a separate worker with input/page/text caps and timeout; on macOS the parser also has a separate read-only Seatbelt profile, no network or Keychain access, and no inherited agent stdin. OCR and stronger document-parser isolation remain future work.

## Commercial release work

Broader model-quality/adversarial evaluations, dependency-aware test environments, stronger supported OS isolation, Windows execution, signed/notarized installers, signed updates, crash recovery, an accessibility audit, and a plugin distribution/update policy remain necessary. This version is a useful local preview with measured boundaries, not frontier-agent equivalence.

## Six memory layers

These are six product layers, not a claim that cognitive science has one universal six-item taxonomy. They follow [LangGraph’s working/long-term distinction and semantic/episodic/procedural memory concepts](https://docs.langchain.com/oss/python/langgraph/memory) and [MemGPT’s external-memory/context movement](https://arxiv.org/abs/2310.08560). No second model or vector database stays resident. SQLite FTS5 indexes stored records; scope and relevance determine a bounded recall payload.

| Layer | Stored information | Write authority / lifetime |
|---|---|---|
| Working context | Current goal, recent goals, broker observations, action status | Host checkpoints per conversation |
| Episodic | Past requests and recorded action outcomes | Host records, capped at 1,500 automatic episodes; replies are not promoted to verified facts |
| Semantic | Explicitly saved facts and knowledge | User-managed, personal or project scoped |
| Procedural | Curated workflow cues and user-saved procedures | User-managed guidance; never executable authority |
| Temporal | Dated information with expiry | Weather evidence expires after five minutes; manual records require expiry |
| Profile | Explicit preferences and personal context | User-managed; removable |

All recalled content is labelled as data with origin, timestamps and scope. About 2,000 characters are selected, then the actual local tokenizer still enforces the total budget. Current intent and the active checkpoint survive compaction. Expired records disappear from the search index. Conversation deletion cascades to linked memories, checkpoints and token metrics. Turning memory off prevents new automatic episodes/recall; existing stored memory can be inspected and cleared. Lexical retrieval is small and predictable, but does not guarantee conceptual synonym recall or retention of every detail.

## Model providers and statistics

Multiple GGUF profiles share one native worker. Switching profiles unloads the old local model. API profiles support stateless Responses, OpenAI-compatible Chat Completions and Anthropic Messages, with catalogue discovery, tool conversion and SSE parsing. Official OpenAI profiles use Responses so reasoning and tools work together, replaying opaque encrypted reasoning/function items. Claude tool loops retain signed thinking blocks. Truncated/incomplete streams cannot authorize tool execution. A provider catalogue does not guarantee that every listed model supports chat/tools. Provider capacity comes from metadata, a verified official registry or a user override, up to 10 million tokens. Cloud profiles now default to their full available capacity, with output reserved within that capacity; a smaller working input budget is an explicit optional setting. Existing 32K budget profiles migrate to full mode. OpenAI API-key profiles use the official input-token counting endpoint including tool schemas; native GGUF uses its tokenizer. Other endpoints use a bundled o200k tokenizer estimate with framing headroom; it is not an exact tokenizer for every provider. Complete old tool exchanges retire before older dialogue, retaining the current request and broker checkpoint. Binary search bounds the number of count operations in long histories. Cloud tool-loop compaction no longer treats the token budget as a character limit. The old 131072 ceiling migrates to 1050000 for the verified OpenAI models. No million-token inference was performed in validation. Missing statistics stay null. Token counters sum actual per-call usage, including repeated inputs; cache counts are not guessed. Local cancellation shuts down the active HTTP socket, including during prefill, while preserving the single worker. Generation rate uses runtime timing or reported output divided by stream generation time.

Keys are stored in macOS Keychain or Windows Credential Manager through native APIs, not SQLite, prompts, logs or the renderer state. HTTPS is mandatory for online endpoints; HTTP is accepted only for loopback local servers. Redirects are refused to avoid forwarding credentials to another endpoint. Selecting an online profile is an explicit privacy boundary: that provider receives included conversation, source and memory context. Request cancellation closes an active remote stream; before headers arrive it may wait for the request timeout. Local protocol fixtures cover Anthropic/Gemini request formatting without paid accounts. Small synthetic OpenAI API probes separately verify live Responses inference and quiz generation; no private project context was transmitted. Effort controls use verified per-model supported sets and actual wire parameters. Explicit catalogue capabilities can override the registry; unfamiliar models are locked to Default until verified.

## Extensions

Skills use pinned local bundles, progressive reference loading and explicit `/skill` selection. Reviewed hook rules and isolated Python decision workers receive bounded events and cannot replace core permissions. Plugins use owned HTTP/stdio workers, deferred reviewed catalogues, native OS-vault/public-client OAuth, versioned package recipes, resources/prompts, rich output and confined media. Effect admission, schema/grant freshness, cancellation and uncertain-outcome recovery remain outside server text. The supported modern mode is explicitly selected; optional subscriptions/tasks/sampling/elicitation and broad server interoperability remain outside the advertised contract.

The pet uses an undecorated transparent topmost window, all-Spaces/full-screen auxiliary collection behavior on macOS, and a compact quick chat. The full workspace stays hidden at launch unless no model is connected yet (a first launch shows its welcome); the tray, the pet and opening Pebble again reveal it. It does not read the screen, request Accessibility permissions, or continuously run inference. Windows topmost/full-screen behavior still needs native validation.

## ChatGPT account sign-in

[OpenAI’s public sign-in flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) uses a Pebble-owned dynamic public registration, random loopback callback, state/nonce and PKCE S256. RS256 identity signatures validate against official JWKS with issuer, audience and expiry checks. Plan-usage and resource-invocation scopes are required. The eligible account model catalogue determines selection. Tokens/rotating refresh records are chunked in the OS vault; SQLite contains only profile metadata. Account refresh is serialized and separate identities cannot overwrite one another. Disconnect clears local credentials and reports whether remote revocation succeeded. No Codex cookie or credential reuse exists.

This feature remains subject to OpenAI’s [current eligibility and preview rules](https://developers.openai.com/siwc/quickstart). Public discovery and protocol/security fixtures passed, and the user reports successful browser consent and subscription inference. The live account catalogue advertises 272000 usable context tokens and an 872000 experimental maximum with experimental access disabled. Pebble uses the available account limit; API-key profiles have separate documented capacities. This account lacks permission for the input-token counting endpoint, so local estimates apply. No large-context subscription inference has been validated.

## Interactive canvas

The model's `UIRender` and `UIUpdate` tools create schema-validated, revisioned form/table/chart/plan/evidence/quiz/diagram or static HTML artifacts. Updates require the running owner and current revision; completed plan/evidence references require resolved receipts from that run. Native history, input, provenance and stop controls remain outside generated content. A required form and its durable native question are published atomically; ordinary answers recheck the binding and share the human inbox/transcript transaction. Stale/historical/foreign/stopped input cannot deliver an answer or approve an effect.

Saved HTML previews are sanitized static snapshots, with bounded element/CSS counts, strict CSP, exact opaque loopback URLs, five-minute expiry and fetch-time revision/owner/permission checks. Inline DOM JavaScript/TypeScript is blocked. No generated-frame input or arbitrary RPC bridge exists. Revocation prevents new fetches; it does not erase static text already displayed.

Native main-window mod review pins the complete version-one manifest/source/digest. Installation stays disabled; enabling is separate and idle-only. Models can run only an enabled mod from the original run snapshot. JavaScriptCore runs in a disposable credential-free macOS sandbox with no DOM/network/files/host callbacks. Mods observe bounded ordinary event data and emit validated native widgets; they cannot answer forms, alter permissions or replace AgentGuard/broker policy. Parent cancellation reaps the group, CPU/wall/output limits apply, and a sampled 128 MiB RSS threshold may briefly overshoot. Quarantining optional presentation does not stop task execution.


## Bounded child agents

Root runs can delegate to bounded child workers recorded in a host-owned SQLite tree (`agent_tree.py`) and executed by `agent_manager.py`. Children never become root runs or acquire a permission mode. Their tools intersect the parent’s list with a safe set: scoped reads/search, ordinary coordination, parent questions and whole-file `ProposePatch` proposals. Write, command, test, connector, native approval and plugin effects are absent. Root, agent, generation and lease identities come from the host, never from model arguments.

Cloud children each use a fresh provider adapter and socket under the shared three-request lane; cancelling a child closes only its own transport. Spawn reserves child steps, seconds and tokens from the root, and every attempt reserves the pinned full context window. Those reservations are conservative accounting, not provider billing. `WaitForAgents` records a durable wait and releases the root executor; settlement, questions, mail or pending human input enqueue one agent-origin wake. Only root promotion turns a child question into a native form, and only its native answer writes human-origin input, which never approves effects. The root reads proposals with `ReadAgentPatch`, accepts fresh child evidence, and `IntegrateAgentPatch` rechecks the baseline before staging the change through Read/Write, provenance, AgentGuard and the existing broker. Restart marks live children interrupted without replay.

## Version 0.4: companion and attachments

Main and companion composers share the configured provider/model profiles, per-model effort and global UI-owned permissions. The small companion uses add-context, shield and brain popovers rather than a row of dense selects. Its add menu includes raster/documents, public URL sources, project selection and terminal proposals; command approval remains in the full workspace. The native pet broker only admits the required methods; its setting method is restricted to permissions. Running tasks lock model/effort/permission changes.

One provider connection can contain up to fifty selected model profiles. API credentials and ChatGPT refresh records belong to the connection ID, preserving original vault ownership. Removing one model retains the shared credential until the last model is removed. Account catalogue caches are scoped to the account connection, and reconnecting from a child model preserves the entire model set. Catalogue capacities and verified effort capabilities remain per model.

The native windows subscribe to Tauri file-drop events and the multi-file picker. Up to three raster/documents may be staged per message. PNG/JPEG/WebP decoding runs in the confined document worker, with 8 MB/16 MP bounds, metadata stripping, 3072-pixel scaling and small previews. Decoded images persist in SQLite with chat/message scope and a 100 MB per-chat cap. Only the three most recent image-bearing messages are reattached to cloud context. GGUF text-only profiles reject image inference before storing a new human message; choose a vision-capable provider. Images are explicit untrusted evidence, never authority. Responses, Anthropic and compatible Chat formats receive their native image parts. Chat deletion removes attachment rows along with memory/checkpoints/artifacts; abandoned staging is cleared on restart.

Avatar expressions are driven by task/tool events and elapsed time, without model calls: attention, curiosity, concentration, testing/review, happy/sad, brief sleepy and impatient reactions. Task IDs vary their cadence. Reduced motion samples a still expression and hidden documents pause animation. A small Keep it / Delete permanently popup handles chat deletion directly.

Version 0.4 is installed in /Applications. The native ARM64 bundle and installer passed signature/checksum validation. Companion screenshot selection, thumbnail, inference to a synthetic loopback vision provider, saved history, metrics, provider filtering, default-only effort locking and the quick Keep it dialog were verified in a separate native QA namespace. Native drop gestures and Windows compatibility were not independently automated.
